# 묶음 통합: 파트별 정리 층 작성 지시 (모든 파트 공통)

이 파일은 `html-brief` 스킬의 묶음 통합 절에서 작성 에이전트에게 그대로 넘긴다.

명령은 묶음 폴더가 있는 작업 디렉터리에서 실행한다. `<스킬폴더>`는 이 스킬이 설치된 곳이다(예: `~/.claude/skills/html-brief`). 답은 유저의 언어로.

## 배경
유저는 여러 HTML로 쪼개진 자료를 싫어한다. 목록 페이지(`<묶음폴더>/00_list_local.html`)에 모인 HTML을 "각 파트별로 1장으로 합쳐서 정리하되, 정보가 손실되지 않게" 만든다. 파트 하나당 파일 하나가 나간다.
- 위층(네가 쓰는 것) = **정리 층**: 그 파트 문서들을 문서 순서가 아니라 **주제 순서로 다시 엮은** html-brief 조각.
- 아래층(build_parts.py가 자동으로 붙임) = **원문 전문**: 각 원문 HTML 전체가 `id="dNN"` 앵커로 붙는다. 그래서 정리 층의 모든 주장은 `<a class="ref" href="#dNN">[NN]</a>` 태그로 원문에 연결한다.
- 파트폴더 = `<묶음폴더>/_build/parts/TN` (bundle_init.py가 만든다).

## 읽을 것
1. `<스킬폴더>/references/authoring.md` — 조각 규격(그대로 따른다). 단 아래 '손실 금지 예외'가 우선.
2. 네 파트 폴더의 `_raw/NN_tK.md` — 원문에서 뽑은 텍스트(표는 행마다 `|` 구분). 숫자·날짜는 여기 있는 것만 쓴다.
3. 필요하면 원문 HTML(각 `_raw` 파일 둘째 줄 `원본:` 경로)을 열어 그림 구성·탭 내용을 확인한다.
- 큰 파일(100KB 넘음)은 통째로 읽지 말고 `grep -n '^#' 파일`로 목차를 먼저 보고, 결론·판정·수치·★·날짜·미결·액션이 있는 절을 골라 읽는다. 모든 문서의 결론·판정은 빠짐없이 담는다.

## 쓸 것
- `<파트폴더>/_build/AUTHORING.md`의 괄호 칸을 채운다(독자=유저와 그 의사결정자, 요청 원문=위 문구 또는 유저의 말, 결론 한 줄, 장 목록=01_main 하나).
- `<파트폴더>/_build/pack.json`의 `lead`를 파트 전체 결론 한 문장으로 바꾼다.
- 조각: `<파트폴더>/_build/pages/01_main.html` (예시 조각을 덮어쓴다). 첫 줄 `<!-- title: … | lead: … -->`, `<h2>` id는 `p01-` 접두사.

## 절 구성 (이 틀 안에서 파트 내용에 맞게 주제 절을 짠다)
1. `p01-map` 이 파트 한눈에: 문서들이 서로 어떻게 이어지는지(누가 무엇의 근거·전제·반론인지) 관계도 SVG. 각 상자에 [NN].
2. 주제 절 6~12개: 문서를 가로질러 같은 주제끼리 묶는다(예: 구조·역할 → 관문·리스크 → 데이터 품질 → 사업성 판정 → 비용 분담 …). 각 절 = 한두 문장 + 그림 1개 이상 + `<details><summary>근거 더 보기</summary>…</details>`. 문서끼리 겹치거나 **충돌**하는 판정·수치는 둘 다 보이고 차이를 그림이나 카드(`card warn`)로 드러낸다.
3. `p01-nums` 숫자·날짜·★ 모음: 파트 전체의 핵심 수치·마감일·★ 미확인 값을 주제별로. 그림 1개(타임라인이나 막대) + details 안에 전부.
4. `p01-todo` 마감·미결·다음 행동: 날짜순 타임라인 그림 + details. 담당자 이름이 원문에 있으면 쓴다.
5. `p01-gap` 없는 문서: 목록 페이지의 '없는 문서' 항목(프롬프트에 있음)을 그림 하나로, 정리 중 발견한 추가 빈칸이 있으면 더한다.
6. `p01-docs` 문서 지도: 문서마다 한 줄(무엇을 다루나, 결론, 원문 분량) + [NN] 링크. 그림 1개(문서별 막대 등) + details.
- 끝에 `p01-src` 출처: 원문 문서 목록(`<a href="#dNN">`)과 원문에 있던 핵심 외부 URL.

## 손실 금지 예외 (authoring.md보다 우선)
- `<details>` 안에서는 `<ul><li>` 목록을 써도 된다(표·blockquote는 여전히 금지). 원문의 판정·수치·날짜·★·미결·담당자를 details 안에 빠짐없이 옮긴다. 원문 문장을 그대로 옮겨도 된다.
- 그림 밖 본문 글자는 그림당 250자 이하를 지킨다(details 안은 세지 않음).
- 새 사실을 만들지 않는다. 문서에 없는 해석·권고 금지. ★는 원문 그대로 유지(`<span class="star">★</span>`). 수치·날짜를 바꾸거나 반올림하지 않는다.
- "|"·">" 를 글 속 구분자로 쓰지 않는다.
- 사진: 원문 폴더의 `_img/`·`_assets/img/` 그림 중 2~4장을 `<파트폴더>/_img/`로 복사해 `_img/파일`로 넣어도 된다(선택).

## 마무리
1. `uv run <스킬폴더>/scripts/check.py <파트폴더>` 오류 0. "근거 없는 숫자" 경고는 전부 확인해 원문 숫자로 고친다.
2. `uv run <스킬폴더>/scripts/build.py <파트폴더>`가 성공하는지 확인(열지 말 것, `open` 금지).
3. 보고(짧게): 절 수, SVG 수, 문서 간 충돌로 표시한 항목, 정리 층에 일부러 넣지 않고 원문 전문에만 남긴 내용 종류.
